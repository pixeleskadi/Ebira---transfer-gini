# Try the native v1 candidate

This development build targets Windows 11 x64 and Android 10+. It is for device validation. Windows is unsigned and Android uses a debug signing key; these are not the owner-signed public release packages.

1. Extract the Windows ZIP into a normal folder. Run `Install-Ebira.cmd` to copy it into your per-user Programs folder and add a Start-menu shortcut, or run `Ebira.exe` directly. Node.js and a separately installed .NET runtime are not required.
2. Install `Ebira-Android-offline-candidate-3.apk` on your phone/tablet using Android's package installer. It uses the same development key as the previous APK, so install it as an update. Public distribution signing is still pending.
3. In Android Ebira, tap **Create offline connection**. Allow Nearby Wi-Fi on Android 13+, or precise Location on Android 10–12. Older Android also needs the system Location switch on; Ebira does not collect location. Wait for the Wi-Fi name and password. The hotspot has no internet access and needs no mobile data. Android may disconnect an existing Wi-Fi connection to create it.
4. In Windows Ebira, click **Open Wi-Fi settings** and join the phone's displayed network. Stay connected when Windows reports **No internet**. Set this personally controlled hotspot's Windows network profile to **Private** and allow Ebira through Windows Firewall on private networks. TCP uses 8443 or an available fallback; local discovery uses UDP 8444. Connection addresses refresh automatically every five seconds, or click **Refresh connection**. No router port forwarding is required.
5. On Android tap **Find my laptop**, select your laptop, and compare BOTH the 12-character pairing code and certificate ending with the Windows Ebira screen. Only tap **Both match · connect** when both match. If discovery is blocked, use the Windows address on the joined Wi-Fi and copy its complete invitation into Android. Windows prefers physical Wi-Fi/Ethernet over detected VPN/virtual adapters such as WARP. Existing private Wi-Fi networks remain supported. QR scanning is not implemented.
6. Check the box beside the named phone in Windows and click **Approve checked**. Its Session column must change to **approved**. Approval and End checked sessions act on checkboxes; clicking a row alone is not enough. Android can now send additional files under that approval. In Windows, keep approved recipients checked and choose Add files to send to them. On Android, use Choose files to send for the other direction. Windows offline candidate 4 fixes the earlier checkbox/row-selection mismatch; Android offline candidate 3 remains compatible.
7. Tap Start / resume transfers on Android to run its visible transfer service. Keep Windows awake. Select sequential or per-file round-robin in Windows when using more than one Android receiver.
8. To resume after interruption, recreate the offline connection if needed, reconnect Windows, reopen both apps, start the Android service and use Resume on any paused jobs. If Windows gets a different IP, find the laptop again and confirm its identity; the same valid approved session is retained. An expired/ended session needs new pairing and new file offers. Keep selected sources unchanged and available until all recipients finish.

Android's **Stop offline connection** button or connection notification stops the private Wi-Fi; transfer progress is retained. Pausing the transfer service alone keeps the hotspot available. Force-stop/reboot removes the hotspot; recreate it manually. The separate connection notification remains until you stop the hotspot or Android stops it. Wi-Fi name/password stay in process memory and are cleared when the service stops.

For band control, **Phone hotspot settings · optional 5 GHz** stops Ebira's automatic hotspot and opens system hotspot settings. Select 5 GHz if offered, join it from Windows, then return to Ebira and find your laptop. Availability and offline operation of the phone-managed hotspot vary by manufacturer. The automatic local-only mode cannot force a band across Android 10+ devices. No speed minimum is promised; measure on your own hardware.

Android photos/videos/audio publish to their respective Ebira media folders after checksum verification. Documents and other files appear under Download/Ebira. Windows receives under Downloads/Ebira by file type. Cancel transfers before cleaning incomplete files. Clearing history never deletes completed received files.

The app records local resume metadata and encrypted credentials. There are no accounts, cloud transfer or analytics. See V1-BASELINE.md for persistence, retention and platform limitations, and DEVICE-VALIDATION.md for the remaining release tests.

Updates are manual: stop Ebira and install the new Windows package into the same folder. Use an APK signed with the same owner-controlled key for Android upgrades; a development APK cannot be upgraded in place by a differently signed release. Back up completed files before uninstalling. User data is retained by the Windows uninstaller; Android uninstall removes private state but keeps published shared files.

Support/defects: use this repository's GitHub Issues. Include device/OS/build, the transfer direction, file size and the exact visible error. Do not post pairing invitations, tokens, private keys, local state or personal file contents.
